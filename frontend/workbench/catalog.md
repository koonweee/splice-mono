## Composition interactions

- Home: change period, hide balances, open an account, hover the graph.
- Transactions: toggle Bulk edit and select rows to expose the sticky toolbar; open filters and a transaction detail drawer; Add transaction opens the manual editor. Desktop widths render TransactionsTable, compact widths render TransactionsMobileList.
- Analysis: Audit opens AnalysisAuditDrawer and its header; select a category to open CategoryTransactionsModal. Wide widths render the Sankey graph; compact widths render its category list.
- Settings: visit Analysis, Categorization, Categories, Access and Recurring tabs to mount each section, then use Add/Edit to inspect its real editor. These sections are intentionally lazy mounted.
- Account dialogs: use the account/add/backfill/holdings state selector to open each actual dialog. Account details expose History, Details, Holdings and Activity tabs and nested editors.
- Lifecycle: offline/update simulate events in the frame; no service worker or badge is registered. Session blocked hides its child through the real PrivateSessionBoundary.

The registry test verifies these references resolve. It does not claim an interaction was visually inspected or that every mocked mutation is complete. Those remain separate implementation/validation gates in the plan.

section actions. It contains no persistence or data ownership; Settings page browser
checks cover moving section actions into the shared header.

uses PageActions, HomePeriodControl, AccountSelect, CategorySelect and shared
Mantine defaults in ready/disabled states. Its boundary toggle is workbench-only.
Checkbox/radio padding activation is nonvisual theme behavior, covered by
`src/lib/design-system/touch-controls.test.tsx` and browser padding taps.

Typography roles are defined in `lib/design-system/typography.ts` and expanded by
`typography-css.ts` for both builds. These nonvisual modules have no component
tile; the Typography roles example renders their actual styles. Policy/compiler
behavior is covered by `scripts/typography-policy.test.mjs` and
`typography-css.test.ts`.

Density review: the real `page-accounts`, `page-settings` (all list sections), and
`page-analysis` examples also support `state=long-content`. This includes linked
accounts needing consent, long category/rule names, archived rules, paused schedules,
and large Analysis totals. `SettingsRowActions` is composed into all four Settings
list sections; `tab=analysis` includes the single-action matching-window case.
