# Audit finding coverage

The [original audit](../../../../docs/backend-speed-and-correctness-audit-2026-09-05.md) maps to these shared implementations and direct regressions. Matched timing evidence is maintained separately in [the benchmark report](../../backend-query-performance.md); correctness corrections are not counted as equivalent-output speedups.

| Finding                                                      | Shared implementation                                                                                            | Direct regression evidence                                                                                                  | Benefits                         |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| Transaction date predicates, full joins and deep offsets     | `TransactionQueryService`, canonical activity-date migration, cursor client                                      | `transaction-query.postgres`, `transaction-page.postgres`, transaction/MCP unit tests, production scroll/filter/edit checks | Web + MCP reads                  |
| Per-date FX query fanout and inconsistent valuation date     | Sparse resolver, exact integer ratios, effective reporting date, input/FX snapshots                              | `currency-exchange.postgres`, HTTP/MCP/cash-flow/balance snapshot races                                                     | Web + MCP reads                  |
| Empty or divergent latest holdings                           | `HoldingsQueryService`, completed headers shared by all callers                                                  | `holdings.postgres`, real editor clear/refresh, MCP portfolio model/host checks                                             | Web + MCP holdings               |
| Repeated cash-flow candidate/rule work and rounding mismatch | One report context per period; indexed matching; once-rounded row sum                                            | `cash-flow.postgres`, randomized matching reference tests, category drilldown reconciliation                                | Web + MCP analysis; combined App |
| Daily history matrix and large chart output                  | Streamed projection, request-local reuse, explicit compact sampling                                              | History/dashboard/balance PostgreSQL and unit tests; separate daily/compact benchmark lanes                                 | Web + MCP history                |
| Per-row banking sync preparation/writes                      | One ordered rule snapshot; chunked identity reads and activity/detail writes                                     | 14 banking-sync PostgreSQL cases, including 5,000 rows, retries/replacements/rollback/events                                | Sync; indirect read contention   |
| Partial or stale investment publication                      | Account locks, generation fencing and atomic batch publication                                                   | Holdings PostgreSQL failure/overlap/stale/empty tests                                                                       | Sync + trustworthy web/MCP reads |
| ETH overflow, precision loss and permissive coercion         | Exact string contracts, numeric(78,0), exact provider/input/formatting paths                                     | Money/provider/migration/HTTP/MCP/frontend tests; exact browser edit; backup/restore rehearsal                              | Web + MCP + ingestion            |
| Lost settings/provider/default updates                       | Locked nested patches and committed events                                                                       | Real concurrent settings/provider/default PostgreSQL tests and stale browser tabs                                           | Shared user state                |
| PAT hydration and timestamp-write overhead                   | Narrow authoritative validation and one usage write per minute                                                   | PostgreSQL ten-request/race/minute tests; separate PAT HTTP benchmark                                                       | PAT HTTP; not Auth0 MCP          |
| Missing latency attribution                                  | Request-local SQL, acquisition and transport metrics; separate process CPU measurements in the benchmark harness | Observability unit/real-pool tests; identical benchmark observer in both variants                                           | Diagnostics for HTTP + MCP       |

The [rigorous 10k comparison](../backend-query/comparison-10000.md) provides repeated latency and query-count evidence for transaction pages/search, FX, holdings, cash flow, matching, daily history, PAT HTTP and the real MCP transport. The [focused comparison](../backend-query/focused/comparison.md) adds 100k/1m scale checks and maps the remaining measured findings to `sync.*`, `auth-settings.*`, `shape.*`, `extended.cursor.*`, `extended.portfolio.*`, compact-history, isolated-memory and mixed-load cases. Its short samples are diagnostic.

Exact-money storage and atomic publication findings use direct corrected-output and failure/race tests rather than claiming speedups from different financial results. [Migration/locking measurements](../migrations/backend-query-2026-09-05.json), [backup/restore recovery](../migrations/exact-money-recovery.json), [paired original correctness probes](../backend-query/probes/before-10000-run1.json), and [the final instrumented edge probes](../backend-query/final-instrumented-smoke/after-10000-run1.json) retain that evidence separately.

The exact list of tasks and exit criteria remains in [the implementation ledger](../../../../plans/backend-query-implementation-ledger.json). No production deployment is included.
